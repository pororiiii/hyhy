# INTERVIEW: 실무자 질문과 답변 기록

실무자에게 무엇을 물어볼지 고르고, 들은 답변을 정리할 때 사용하는 자료야. 담당 AI는 사용자가 전달한 인터뷰 원문이나 자료를 근거로 아래 기록을 작성해. 실무자만 아는 내용은 답을 추측하지 말고 실무자에게 확인할 질문으로 제안해.

## 질문 순서

실제 사례 → 현재 처리 방법 → 소요 시간·건수 → 관련 사람 → 제약·승인 조건 순서로 확인해. 질문은 한 번에 하나씩 하고, 답을 들으면 이해한 내용을 짧게 되짚어. 처음부터 자동화나 AI 사용을 해법으로 정하지 마.

## 질문 카드 7개

1. 실제 사례: 가장 최근에 이 문제로 막혔던 일을 처음부터 들려줄래?
2. 현재 처리 방법: 그때 지금 도구로 어떻게 해결했어? 어디서 손으로 옮기거나 다시 확인했어?
3. 소요 시간·건수: 얼마나 자주 생기고 한 건에 몇 분 걸려? 그 숫자는 어디서 확인할 수 있어?
4. 관련 사람: 누가 입력하고 누가 판단해? 틀리면 누가 가장 곤란해져?
5. 제약·승인 조건: 절대 자동으로 처리하면 안 되는 일과 꼭 사람이 승인해야 하는 일은 뭐야?
6. 데이터·유지: 실제 원본 자료는 어디 있어? 사용 권한은 있고, 내가 떠난 뒤 누가 관리해?
7. 성공 확인: 이번엔 어느 병목 하나를 줄일까? 현재값·목표값·측정 방법을 이렇게 적으면 맞아?

## 답변 기록

담당 AI가 답변을 받은 뒤 해당하는 내용을 아래에 기록해. `____`는 실제 내용을 적을 자리야. 아직 답을 받지 못한 내용은 모르는 것으로 남기고, 제안을 합의된 내용으로 바꾸지 마.

- 확인한 사실: ____ / 근거가 되는 실무자 발언·자료 위치: ____
- 모르는 것: ____ / 다음에 확인할 질문과 확인할 사람: ____
- 내 제안: ____ / 아직 제안 중인지, 누구에게 무엇을 확인받았는지: ____

실무자가 말한 수치와 자료로 직접 확인한 수치는 구분해. 원문에 없는 내용은 사실로 추가하지 마.

## 답이 막연하거나 정보가 부족할 때

- “보통 그래”라고 하면: 최근 한 건만 예로 들어줄래?
- 숫자가 없으면: 지금 확인 가능한 건수나 표본이 있어? 없으면 미확인으로 남기고, 추정치가 나오면 추정이라고 표시할게.
- 여러 문제가 나오면: 오늘 하나만 풀 수 있다면 뭐가 가장 비싸거나 자주 생겨?
- 입력이 불명확하면: 실제 형식의 익명 예시와 잘못 들어온 예시를 하나씩 볼 수 있어?
- 예외가 없다고 하면: 빈 값·중복·잘못된 날짜·외부 서비스 실패 때 지금은 어떻게 해?
- 위험한 판단이면: 승인자는 누구고, 승인 전·거절 후 상태는 어떻게 보여야 해?
- 시간이 부족하면: 오늘 안 만들어도 되는 것부터 합의할까?
