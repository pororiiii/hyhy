# 개인 FDE 키트 설치 안내

이 키트는 과제에 사용할 작업 원칙·기록 양식·기능별 참고 코드 안내서·스킬 원문을 실제 과제 폴더에 배치합니다. 이 README는 설치용 안내이고, `docs/USER_README.md`는 나중에 만든 도구의 사용 설명서를 작성하는 양식입니다.

## AI에게 할 요청

공개 저장소 링크와 함께 다음처럼 요청하세요.

> 이 저장소의 개인 FDE 키트 README를 읽고, 현재 과제 작업 폴더에 설치해줘. 기존 파일은 보존하고, 설치 후 실제 파일 위치와 아직 준비되지 않은 항목을 알려줘.

## 설치를 맡은 AI의 절차

1. 현재 작업 폴더와 과제 파일을 확인해 **실제 과제 폴더의 절대 경로**를 정한다. 키트를 내려받은 폴더와 혼동하지 않는다. 대상이 불분명하면 사용자에게 확인한다.
2. 사용자가 준 공개 저장소를 과제 폴더와 구분되는 위치에 내려받는다. 이미 내려받았다면 내용을 확인하고 재사용한다. 이 README와 `install.sh`가 함께 있는 폴더가 키트 원본이다. 저장소 안에서 `fde-kit-custom/` 같은 하위 폴더에 있을 수도 있다.
3. 아래 명령의 두 경로를 실제 값으로 바꿔 실행한다. 대상 과제 폴더는 미리 존재해야 한다.

   ```bash
   bash "/키트/절대경로/install.sh" --target "/실제/과제/폴더"
   ```

4. 종료 결과와 출력된 파일 경로를 확인한다. 실패하거나 충돌이 남아 있으면 설치 완료로 보고하지 않는다. 성공하면 과제 폴더의 `AGENTS.md`를 읽고 작업 원칙을 확인한다.
5. 설치 대상과 배치된 파일, 미포함·미완성 항목을 사용자에게 보고한다. **파일 배치 성공과 키트 전체 완성은 구분한다.**

스크립트에는 Bash와 기본 파일 명령이 필요합니다. 저장소를 내려받는 데는 Git과 네트워크 접근이 필요하며, 설치 스크립트 자체는 네트워크 접속이나 패키지 설치를 하지 않습니다. 공개 저장소의 주소는 사용자가 제공한 값을 사용하세요.

STATE는 처음에 ‘등록된 작업 없음’으로 설치됩니다. 작업을 맡은 AI가 AGENTS의 ‘작업 현황’ 규칙에 따라 작업별 담당·수정 파일·진행 상황을 기록하고 갱신합니다. 프로젝트의 6단계를 관리하는 양식은 사용하지 않습니다.

## 기능별 참고 코드 찾기

`REPOS.md`에는 12개 분류의 40개 기능 항목과 15개 공식 저장소를 정리했습니다. 필요한 기능을 찾으면 실제 파일·함수, 참고할 부분, 함께 필요한 파일·환경, 한계를 볼 수 있습니다. AI는 AGENTS의 안내에 따라 구현 계획이나 참고 코드를 고를 때 관련 항목을 먼저 확인합니다.

맨 위 목차에 12개 분류와 각 분류의 기능을 모두 나열했습니다. 사용자는 각 항목의 **예시 상황·동작 예시·참고 코드가 제공하는 부분·따로 만들거나 정할 부분**을 읽으면 됩니다. 가상의 점검 요청 목록과 실제 입력값을 예로 들어, 사용자가 무엇을 하면 화면이나 결과가 어떻게 바뀌는지 설명했습니다. 파일 경로·함수·실행 환경은 **「AI가 참고할 기술 정보」**를 펼쳐 볼 수 있도록 구분했습니다.

> REPOS.md에서 이번 과제에 필요한 기능을 찾아, 어느 코드의 어떤 부분을 참고할지 설명해줘.

2026-10-29에 실제 소스를 읽고 특정 커밋으로 링크를 고정했습니다. 참고 프로젝트의 실행은 모두 미검증이며, 실행 코드 묶음은 포함하지 않습니다. 완성 앱의 일부와 조합해서 써야 하는 라이브러리 예제를 구별했고, 확인하지 못한 기능도 명시했습니다.

## Handoff 사용

설치 후 AI에게 “현재 작업을 handoff해줘”라고 요청하면 됩니다. AGENTS는 요청을 받은 AI가 `skills/handoff/SKILL.md`를 읽고 인계 기록을 작성하도록 안내합니다. HANDOFF는 처음에는 제목만 있으며, 실제 인계 기록을 최신순으로 쌓습니다. 1~6단계의 상태는 인계 시점에 AI가 근거를 보고 판단하며, 사용자가 단계 번호나 전환을 지정할 필요는 없습니다.

## Deep Interview와 Plan 사용

기존에 만든 독립형 스킬을 포함했습니다. Deep Interview는 질문을 통해 요구사항을 구체화하고, Plan은 구현 순서·완료 기준·검증 방법을 계획합니다. Plan의 실제 스킬 이름은 `plan`입니다. Plan 메뉴의 기본 요청문에는 `--direct`를 넣지 않아, 요구사항이 불분명하면 질문하고 충분히 정리돼 있으면 바로 계획하는 기존 선택 기준을 따릅니다.

Deep Interview는 `.deep-interview/runs/인터뷰-ID/`마다 진행 기록·맥락·인터뷰 요약·명세를 따로 저장합니다. 시작할 때 알려준 경로로 다른 창에서 이어갈 수 있으며, 기존 담당이 쓰기를 끝냈는지 확인한 뒤 인수합니다. 여러 인터뷰 중 어느 것을 이어갈지 불분명하면 AI가 먼저 확인합니다. 기존 공용 기록은 지우지 않고, 재개 시 확인한 내용을 새 폴더로 복사합니다. OMX의 자동 잠금·세션 확인 기능까지 제공하는 방식은 아닙니다.

스킬 메뉴에 등록하기 전에도 과제 폴더에서 AI에게 파일을 지정해 요청할 수 있습니다.

> skills/deep-interview/SKILL.md를 읽고 그 절차대로 인터뷰를 진행해줘.

> skills/plan/SKILL.md를 읽고 그 절차대로 지금까지 합의한 요구사항의 구현 계획을 작성해줘.

이 설치기는 다섯 스킬의 지침과 함께 제공된 파일을 과제 폴더에 배치합니다. 사용 중인 AI 도구의 `/` 메뉴나 `$handoff`, `$deep-interview`, `$plan`, `$team`, `$ultragoal` 호출 목록에 등록하는 기능은 포함하지 않습니다. 해당 방식으로 호출하려면 설치를 맡은 AI가 실제 환경의 스킬 등록 방법을 확인해 별도로 설치해야 합니다. 같은 이름의 스킬이 이미 있다면 내용을 비교하고, 임의로 덮어쓰지 않습니다.

## Team 사용

Team은 **tmux 창마다 Codex를 실행해 일을 나눠 맡기고, 주 AI가 결과를 모아 검증하는 스킬**입니다. 예를 들어 한 AI는 CSV 처리 함수를 구현하고, 다른 AI는 그 구현을 기다릴 필요가 없는 원본 자료의 오류 조건을 검토할 수 있습니다. 같은 파일을 동시에 수정하는 작업은 분리하지 않습니다.

> skills/team/SKILL.md를 읽고, 합의된 작업 중 독립적으로 진행할 수 있는 일을 나눠 팀으로 실행해줘. 끝나면 결과를 검증해줘.

Python 3.10 이상·tmux·이미 실행 가능한 Codex CLI가 필요합니다. OMX는 설치하지 않으며 모델·인증·Codex 설정을 바꾸지 않습니다. **별도로 실행한 Codex가 현재 채팅과 같은 설정을 사용한다고 보장하지는 않으므로**, 실제 CLI가 시험에서 허용된 상태인지 먼저 확인합니다. tmux 사용 가능과 시험의 모델·동시 실행 허용은 별개입니다.

스킬 옆의 `team.py`는 창 실행·진행 기록·종료를 담당하는 파일이고, `operations.md`는 이를 사용하는 AI용 설명입니다. 사용자가 직접 명령을 외울 필요는 없습니다. 실행 결과는 과제 폴더의 `.team-standalone/`에 남으며 AI가 종료했다고 보고하는 것과 주 AI가 결과를 검증한 것을 구분합니다.

원본 OMX Team의 **작업 분담·병렬 실행·결과 검증·종료 확인**을 옮겼습니다. 실시간 지시 전달·자동 재배정·자동 작업 폴더 분리·다른 AI 제품과의 혼합 실행은 포함하지 않았습니다. 원본 Team과 동일한 기능이나 성능을 보장하는 버전은 아닙니다.

## Ultragoal 사용

Ultragoal은 **합의된 계획을 한 작업씩 실행·검증하고, 보고한 뒤 멈추는 스킬**입니다. 사용자가 ‘계속’이라고 하면 다음 작업 하나를 진행합니다. Plan으로 만들 순서와 구성을 정했다면, Ultragoal은 그 계획의 실행과 완료 확인을 맡습니다. 예를 들어 CSV 읽기를 끝내 보고한 뒤, 다음 진행 요청을 받으면 오류 판정을 만듭니다.

> skills/ultragoal/SKILL.md를 읽고 합의된 계획을 한 작업씩 실행·검증해줘. 매번 보고한 뒤 내가 계속하라고 할 때까지 멈춰줘.

**tmux·OMX·추가 프로그램 설치는 필요 없습니다.** 현재 AI가 파일을 수정하고 과제에 필요한 검증을 실행할 수 있어야 합니다. 선택적으로 Codex의 `/goal`에 해당하는 도구를 연결하며, 도구가 없는 환경에서는 파일 기록을 따라 진행합니다. 파일만으로 대화 종료 뒤 자동 실행이 보장되지는 않습니다.

작업을 시작하면 `.ultragoal/실행-ID/`에 목표 설명·현재 진행·변경 이력을 남깁니다. 원본의 마지막 검토 절차를 유지하므로, 별도 검토자를 사용할 수 없으면 구현 결과를 남기고 ‘검토 대기’로 보고합니다. 자동 파일 잠금이나 다른 세션의 기록 보호 기능을 제공하는 버전은 아닙니다. 원본과의 차이와 자세한 기록 방법은 스킬 안의 AI용 설명에 있습니다.

## 기존 파일과 재설치

- 같은 경로의 파일 내용이 원본과 같으면 그대로 유지합니다.
- 내용이 다르거나 파일 자리에 폴더·심볼릭 링크가 있으면, 사전 검사에서 충돌 경로를 알리고 복사 전에 중단합니다. `docs`, `skills`와 설치 대상 스킬의 하위 폴더가 일반 폴더가 아닌 경우에도 중단합니다.
- 기존 파일을 덮어쓰거나 AGENTS에 규칙을 자동으로 덧붙이지 않습니다. `.kit` 같은 다른 이름으로 우회하지 않습니다.
- 설치 AI는 충돌한 기존 내용과 키트 내용을 비교해 상황을 설명해야 합니다. 설치를 성공시키기 위해 기존 기록을 지우거나 다른 곳으로 치우지 마세요. 필요한 통합 방식은 해당 내용을 확인한 뒤 정합니다.
- 사용 중인 STATE처럼 원본과 달라진 파일도 보존합니다. 이 설치기는 새 문서를 배치하는 도구이며, 작성 중인 기록을 초기화하거나 기존 프로젝트를 자동 갱신하지 않습니다.
- 설치 중 쓰기 실패나 다른 작업의 변경이 발생하면 일부 파일만 배치될 수 있습니다. 오류 메시지와 실제 파일을 확인하고, 실패를 완료로 보고하지 마세요.

## 현재 준비 상태

- AGREEMENT와 SPEC을 포함한 문서 양식은 선택한 내용으로 정리했습니다. 실제 과제의 합의·구현 내용은 작업하면서 기록합니다.
- REPOS의 기능별 코드 안내와 설치 경로를 포함했습니다. 실제 과제의 기술 환경·업무 규칙에 맞춰 적용하고 검증해야 합니다.
- Handoff·Deep Interview·Plan 스킬을 포함했습니다. Deep Interview의 질문·점수·종료 조건은 유지하고 저장·재개를 인터뷰별로 분리했습니다. Plan은 메뉴의 기본 요청문에서 `--direct`를 제거했으며 지침과 라이선스는 보존했습니다.
- Team의 지침·실행 파일·사용 설명·라이선스를 포함했습니다. 실제 tmux와 모의 Codex를 이용한 실행 검사와 오류 모의 검사를 합쳐, 병렬 실행·실패·중단·다른 세션 보존·macOS 파일명 대소문자 충돌 등 15개 테스트를 통과했습니다. 실제 AI의 작업 품질과 시험 환경의 실행 가능 여부는 미검증입니다.
- Ultragoal은 별도 실행 프로그램 없이 지침과 파일 기록으로 운영합니다. 새 작업 실행과 완료 기록이 틀린 작업의 재개, 두 가지 격리된 모의 사용 및 23파일 설치를 확인했습니다. 실제 Goal 도구 연결, 시험 환경의 보조 에이전트 지원과 장시간 자동 실행은 미검증입니다.
- 로컬 파일 배치·재설치는 확인했습니다. Deep Interview의 기존 `argument-hint` 필드는 Codex용 `quick_validate.py` 형식 검사에서 허용되지 않았습니다. 해당 필드는 보존했으며, 실제 도구의 스킬 등록·메뉴 호출 호환성은 별도 확인이 필요합니다.
